## Invocation and compatibility rules

- C# callers use a fully qualified executable path, `UseShellExecute = false`, and `ProcessStartInfo.ArgumentList`; pass one argument per item. Redirect and drain stdout and stderr concurrently. Decode JSON output as UTF-8. Never build a shell command string.
- Timeouts above are **caller-enforced**, not CLI-internal timers. On timeout, kill the process tree, discard partial stdout/artifacts, and route the invoice to review; never treat timeout as a successful extraction.
- The E-02 `--context` is producer-owned and required for `--image`. The CLI does not synthesize identifiers, customer data, or product names. `--out` and `--e05-bank` are capture-folder-only; `--context`, `--multi-evidence`, and `--drift-report` are not accepted in capture-folder mode.
- `onboard build` requires explicit currency (`rial` or `toman`). The E-20 route is synthetic mechanics-only and is never production training evidence. Explicit timestamps (`--created-at`, `--evaluated-at`, `--detected-at`, `--exported-at`) are required for byte-stable golden invocations; production callers may omit them where the command permits.
- JSON artifact writers write UTF-8 bytes directly, without BOM, with LF line endings and a final LF. JSON on stdout is written through the binary stream. Golden outputs are checked byte-for-byte; diagnostics are intentionally not compared because they may contain caller paths.
- Exit `10` is a completed, fail-closed review—not a process failure. Exit `20` is a blocked/reject route. Exit `30` is a bridge/input/runtime failure; it must not be interpreted as an invoice result.
