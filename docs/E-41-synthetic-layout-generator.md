# E-41 — مولد seeded برای layoutهای کاملاً synthetic

## دامنه و ایمنی داده

`src/synthetic_layout_generator.py` فقط از دو ورودی `seed` و `count` نمونه می‌سازد؛ هیچ fixture، تصویر یا فایل منبعِ فروشگاهی، دادهٔ Holoo، نام/تلفن/نشانی مشتری یا شبکه‌ای را به‌عنوان ورودی مصرف نمی‌کند؛ برای رسم از فونت داخلی Pillow استفاده می‌کند. متن تصویر و نام کالاها ساختگی‌اند و manifest هر ردیف را با `SYNTHETIC ONLY — NOT CUSTOMER DATA` علامت می‌زند. این خروجی دادهٔ production، معیار دقت OCR یا قرارداد Canonical Invoice نیست.

## اجرا

از ریشهٔ مخزن، در محیط دارای Pillow:

```sh
python scripts/generate_synthetic_layouts.py \
  --seed 20261108 \
  --count 12 \
  --out-dir /tmp/e41-synthetic
```

`seed` باید عدد صحیح نامنفیِ ۶۴‌بیتی باشد؛ `count` در بازهٔ 1 تا 100 است. پوشهٔ خروجی باید تازه یا خالی باشد تا خروجی قبلی ناخواسته بازنویسی نشود. فرمان برای هر نمونه یک PNG و در پایان `manifest.json` می‌نویسد. Manifest، seed، شناسهٔ نسخهٔ مولد، profile چیدمان، مختصات پنج مرز ستون/ردیف، مقادیر عددیِ اعلام‌شده و SHA-256 هر PNG را ثبت می‌کند.

مولد از تابع‌های hash دامنه‌دار و seed استفاده می‌کند؛ اجرای دوباره با seed/count یکسان در همان محیط، bytes یکسانِ manifest و PNG می‌دهد. چهار profile چیدمان از پیش تعریف‌شده‌اند: استاندارد، شرح عریض، شرح باریک و grid جابه‌جا‌شده. مقادیر تعداد/مبلغ هم از همان seed مشتق می‌شوند؛ جمع ردیف‌ها و payable در manifest صرفاً برچسب‌های تستی‌اند.

## کنترل‌ها

```sh
PYTHONPATH=src python -m pytest -q tests/test_e41_synthetic_layout_generator.py
```

تست‌ها تکرارپذیری bytes، تفاوت seedها، نبود کلیدهای اطلاعات مشتری، امتناع از بازنویسی پوشهٔ غیرخالی، تطبیق grid/تعداد ردیف‌های manifest با projection detector و یافتن ناحیهٔ payable را کنترل می‌کنند. هیچ‌یک از این کنترل‌ها OCR یا استخراج عددی از تصویر را اندازه‌گیری نمی‌کند؛ هر ادعای دقت باید در harness جداگانه با معیارهای مستقل سنجیده شود. این مولد نوع یا قاعده‌ای برای v1.1 تعریف نمی‌کند.
