# پیش‌نویس افزایشی Canonical Invoice v1.2 — فقط برای بازبینی

**وضعیت: پیش‌نویس پیشنهادی و غیرمصوب.** این فایل‌ها به‌صورت افزایشی تازه‌اند؛ هیچ قرارداد منجمد، شِما یا رفتار اجرایی موجود ویرایش نشده است. این پیش‌نویس به‌تنهایی مجوز پیاده‌سازی، ذخیره‌سازی یا انتشار نیست.

## دامنهٔ محدود

شِمای `schemas/canonical_invoice_v1_2_draft_addendum.schema.json` یک ضمیمهٔ پیشنهادی برای رکورد موجود است که با `invoice_id` به Canonical Invoice v0 متصل می‌شود. سه مورد پیشنهادی:

1. **پرداخت cheque:** نوع ثبت‌شدهٔ پرداختِ `cheque` افزوده می‌شود؛ پرداخت همچنان شامل نوع و مبلغ عدد صحیح است. شمارهٔ حساب، تصویر برگه، سررسید، وصول یا وضعیت بانکی در این دامنه نیست.
2. **تخفیف سطح فاکتور:** `invoice_discount` مقدار ثبت‌شده و provenance دارد. `null` یعنی مقدار موجود نیست؛ صفر یعنی صفر به‌طور صریح ثبت شده است. این فیلد تخفیف ردیف را جایگزین نمی‌کند و هیچ تخصیص، محاسبهٔ مبلغ قابل پرداخت یا آشتی عددی تعریف نمی‌کند.
3. **پرچم مشتری حضوری:** `walk_in_customer` مقدار `true` یا `false` دارد؛ `null` یعنی نامعلوم. این مقدار از نبود شناسه یا اطلاعات تماس استنتاج نمی‌شود.

مبلغ‌های ضمیمه عددهای صحیحِ بدون مقیاس در `currency_unit` صریح (`rial` یا `toman`) هستند. `null` واحد، دادهٔ ثبت‌شده را حذف نمی‌کند اما برای هر مصرفی که واحد لازم دارد ابهام ایجاد می‌کند؛ عامل مصرف‌کننده باید آن را در `REVIEW` نگه دارد و تبدیل نکند. هیچ معنای محاسباتی، حسابداری، حقوقی یا مالیاتی به فیلدها نسبت داده نمی‌شود.

## بردارهای طلایی بین‌تیمی

- `tests/golden/e72/canonical-invoice-v1-2-draft-vector.json` تنها بردار فعلی است و همهٔ مقدارهایش ساختگی‌اند. بخش `base_invoice` برای بازبینی مصرف‌کنندهٔ C# با قرارداد بین‌مخزنیِ منجمد E-11 در `contracts/canonical_invoice_v0.schema.json` اعتبارسنجی می‌شود؛ ضمیمه با شِمای تازهٔ پیش‌نویس بررسی می‌شود. شِمای قدیمی‌تر `schemas/canonical_invoice_v0.json` شکل خروجی E-01 در خط Python را تعریف می‌کند و در این crosswalk استفاده یا تغییر داده نمی‌شود.
- فایل بردار برای مقایسهٔ byte-for-byte به صورت JSON فشردهٔ UTF-8 است: کلیدها به ترتیب واژه‌نامه‌ای، بدون فاصله، بدون BOM و بدون newline پایانی؛ آرایه‌ها به همان ترتیب می‌مانند. عددها صحیح‌اند. C# و PHP می‌توانند خروجی خود را با همان قرارداد بایت یا SHA-256 ثبت‌شده در `manifest.json` مقایسه کنند.
- `scripts/verify_e72_vectors.py` اندازه، SHA-256، ترتیب/فشرده‌سازی بایت‌ها، قرارداد E-11 مصرف‌کنندهٔ C# و شِمای ضمیمه را بررسی می‌کند. تغییر vector مستلزم بازبینی مشترک و به‌روزرسانی صریح manifest است؛ آزمون آن را خودکار بازنویسی نمی‌کند.

## موارد باز برای مالک

این سند دربارهٔ اینکه cheque کدام جزئیات را ذخیره کند، آیا مبلغ تخفیف منفی مجاز است، مرز provenance، جایگاه پرچم حضوری در مدل customer و رابطهٔ ضمیمه با فیلدهای نسخهٔ 1.1 تصمیم نهایی نمی‌گیرد. تا زمانی که این موارد و خودِ دامنه به‌صراحت تصویب نشوند، پیش‌نویس نباید به مسیر runtime، ذخیره‌سازی، API یا migration متصل شود.
