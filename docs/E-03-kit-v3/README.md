## Unit-price entry and printed layout

Holo computes each line from quantity × unit price. The guide's fourth column, **“Enter this price in Holo only”**, tells the operator which integer to enter in Holo's existing unit-price input field. The column is an entry aid only: it is **not part of the printed invoice layout and not part of extraction ground truth**. The intended printed target contains the Persian item name, quantity, line total, and invoice-level payable—not a unit-price column. Do not add the guide column to a print form; if Holo cannot produce the required print layout without printing unit price, stop and ask the owner rather than changing these targets.

Run `python scripts/verify_e03_kit_v3.py` from the repository root before entry. The checker proves for every row that quantity × entry-only unit price equals the target line total, checks that each payable equals the sum of its line totals, and verifies that the rendered page values match the answer key. Its generated coverage matrix uses only quantities, line totals, and payable; unit prices and item names are excluded.

## Safety decision

**Holo («هلو») test invoices contain fabricated data only. No real customer, sale, or stock movement occurs. There is nothing to cancel, delete, or roll back. The Holo print job itself is the test artifact; the fake invoice may be discarded.**

Do not use or enter real customer, sale, or stock data. Do not add numeric extraction truth outside the specified quantities, line totals, and invoice-level payable. If the Holo test path would require an unapproved real sale or stock movement, stop rather than substituting another print source.

## Required Holo → SPL → PNG capture

1. Run `python scripts/verify_e03_kit_v3.py` and select one of the four guides. Enter its Persian item names, quantities, and the provided unit prices into Holo. Confirm Holo's calculated line totals exactly match the guide; do not edit the expected values to accommodate a mismatch.
2. Confirm the Holo print form has no unit-price column. Print that fabricated invoice from the actual Holo Windows application to the intended printer queue. Each guide is one source page and one Holo print job.
3. While the real job is in the Windows spooler, use KandooPrintProbe to capture the actual `.SPL` and convert that SPL to its `.PNG`. Keep both artifacts together for traceability.
4. Have KandooPrintProbe write a `Report.txt` beside the artifacts with the printer, Windows spool job ID, timestamp (ISO 8601 with explicit offset), and page count. Example minimum fields:

   ```text
   Printer: <Windows printer queue name>
   Spool job ID: <Windows spool job ID>
   Timestamp: <ISO-8601 timestamp with zone offset>
   Page count: 1
   ```

5. Do not substitute a phone scan, screenshot, word-processor print, generated image, or reconstructed SPL. A PNG or report file alone does not prove the origin or conversion of a capture.

The v3 checker validates authored values, exact arithmetic, and glyph coverage; it does not capture Windows spool jobs or certify Probe origin/conversion. **Print-capture verification is still required from the owner.** No Windows printer, Holo installation, or Holo print job is available in Arena, so no actual SPL capture or SPL-to-PNG conversion is claimed.
