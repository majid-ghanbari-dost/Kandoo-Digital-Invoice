# O15 — Technical decisions made

- **E-60 source baseline:** I port only extractor/CLI/runtime assets identified by `docs/o15-source-provenance.json` from `origin/main` at `180b279b6c692f841cab739577ad4fedeefb77c3` as additive files on the assigned branch; this avoids duplicating the image pipeline while preserving the branch boundary, and a merge/rebase or reimplementation from text-only `src/pipeline/` was rejected.
- **E-60 CLI/build:** Keep the existing extractor CLI protocol and exit codes (0 ready, 10 review, 20 blocked/reject, 30 input/runtime error), package it as a PyInstaller Windows one-folder app, and pin Pillow/jsonschema; a new CLI protocol or Tesseract dependency was rejected.
- **E-60 cross-platform evidence:** Use a committed, explicitly synthetic capture folder and compare exact UTF-8/LF JSON bytes against one shared golden on Ubuntu source mode and the Windows executable; using any owner capture or raw owner result in CI was rejected.
- **E-60 Canonical output:** Require producer-supplied context for Canonical Invoice v0 and preserve explicitly supplied v1.1 recorded fields as a separate, schema-checked object; never infer identifiers/customer/products or merge v1.1 extension fields into frozen v0, and reject implicit/default context.
- **E-60 frozen resources:** Resolve schemas and Glyph assets from PyInstaller's `_MEIPASS`/`_internal` when frozen and from the repository root in source mode; assuming `__file__.parents[2]` is the project root in both modes was rejected.
- **E-60 CI diagnostics:** Emit a bounded unified diff of synthetic golden bytes in the GitHub Actions error annotation, because hosted raw job logs are not reliably retrievable; exposing owner data or trusting only opaque exit codes was rejected.
- **E-60 demo byte stability:** Normalize subprocess diagnostic CRLF/CR to LF before serializing `canonical_note`; preserving host-native stderr newlines in the cross-platform golden was rejected.
- **E-61 evidence contract:** Keep `capture-folder-result-v1`, Canonical v0, and C-84's value/confidence/crop-region shape unchanged; write field value/confidence/reason and half-open image-pixel crop coordinates to a separate local-only `o15.review-evidence.v1` sidecar with an offline, embedded-crop HTML queue; adding fields to the frozen result or writing absolute source paths was rejected.
- **E-61 layout routing:** A readable but unrecognized/incomplete layout remains `REVIEW`, while no detected table geometry remains `BLOCKED` because there is no safe field region to extract; lowering the existing confidence threshold or changing the no-geometry E-60 golden was rejected.
- **E-61 accuracy reporting:** Report `NOT_SCORED` and `extracted_but_wrong: null` without independent expected-value labels; claiming zero errors from a no-field synthetic smoke or tuning on one owner capture was rejected.
