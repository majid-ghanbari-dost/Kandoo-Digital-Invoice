## 1. Holoo source fields that need mapping

**REQUIRES REAL-HOLOO EVIDENCE.** The WP-11.1 spike mechanism deliberately
contains NO guessed schema (D-04/§2.7): field discovery happens per-source
via the spike's read-only PRAGMA discovery + DECLARED operator mapping. The
candidate FIELD GROUPS to map are: invoice header (number/date/totals),
invoice lines (product/quantity/price), customer identity, product identity.
The EXACT table/column names must come from a real Holoo source operated by
the PO/operator (spike report output), or from explicitly provided schema
documentation/evidence. No agent-side guessing.

## 2. Source authority per field/group

**REQUIRES PO DECISION.** Which source is authoritative when Holoo and a
captured document disagree (e.g., Holoo total vs. document total) is a
business-truth decision absent from the Baseline. Note the interaction with
D-01 (resolution order EXTRACTED→DERIVED→UNRESOLVED applies INSIDE the
pipeline; it does not decide HOLOO-vs-document authority).

## 3. Identity authority

**PARTIALLY FROZEN / PARTIALLY REQUIRES PO DECISION.** FROZEN: identity
VOCABULARY and mechanics — D-02 (S1/S2/CAPTURE_SCOPED + Canonical invoice_id
issued only by Kandoo) binds ANY adapter; an adapter may only supply an
External Document Identity where D-02 allows it ("قطعی اگر Adapter شناسهٔ
سند را قطعی بدهد" — deterministic if the adapter gives a deterministic
source id). REQUIRES PO DECISION: whether Holoo's internal invoice id may
serve as that deterministic External Document Identity (and with what
stability guarantee across Holoo edits/reprints).

## 4. Accounting truth authority

**REQUIRES PO DECISION.** Whether Holoo remains the accounting system of
record, or Kandoo-derived values become authoritative for any accounting
purpose, is nowhere decided. (Related: AD-03 FROZEN only pins the INVENTORY
boundary for External Capture in the MVP.)

## 5. Synchronization direction

**REQUIRES PO DECISION.** D-04 fixes the PATH (Holoo DB → Adapter →
Canonical — one direction INTO Canonical) but not the operational sync
model (one-shot import? continuous? user-triggered?). Any Holoo-ward
write-back is separately decided (item 9). DEF1 already blocks
External→Sale.

## 6. Synchronization frequency/trigger

**REQUIRES PO DECISION.** Pull/push, interval, trigger events — operational
semantics absent from the Baseline.

## 7. Conflict semantics

**REQUIRES PO DECISION** (with a FROZEN floor). Floor (FROZEN, already
binding): conflicts inside the pipeline resolve per D-03 —
ambiguous/contradictory cases go to REVIEW; nothing is silently
auto-resolved; the Canonicalization Gate routes uncertainty (G1..G6). Open
PO decision: what happens when Holoo data itself conflicts with a
previously Canonicalized invoice (correction? supersede? nothing?) —
interacts with WP-10.1's frozen lifecycle (SUPERSEDE requires an explicit
verified act; nothing is automatic).

## 8. Enrichment semantics

**REQUIRES PO DECISION.** "Enrichment" is named in D-04 but never defined:
which Holoo-sourced attributes may attach to WHAT (a Canonical invoice? a
customer link? a product candidate?), and whether enrichment happens
BEFORE the Canonicalization Gate (as pipeline input) or AFTER (as
annotation). The agent made no assumption. Note the frozen constraints any
answer must respect: D-06 (no auto-create Customer), D-05 (fuzzy/candidate
policies are implementation-level, WP-8.2 pending PO), AD-03 (no inventory
effects).

## 9. Write-back policy

**FROZEN (negative) + REQUIRES PO DECISION (any positive).** FROZEN: WP-11.1
is READ-ONLY absolutely; DEF1 keeps External→Sale out of the MVP; AD-03
blocks inventory effects. Any future Holoo write-back is therefore a NEW PO
decision (explicitly outside the current freeze).

## 10. Whether any Holoo data may affect Canonical Invoice

**REQUIRES PO DECISION (gating all other items).** D-04 fixes the PIPE
(Holoo DB → Adapter/Enrichment → Canonical) but the PO has never decided
WHETHER to open this flow in the current product stage, and if so, which
fields/groups (item 1) enter THROUGH the Canonicalization Gate (item 12)
versus remain observational (item 11). AS-01 (External Flow through every
frozen layer) and the Gate's role are FROZEN constraints on any "yes".

## 11. Which data remains observational only

**REQUIRES PO DECISION.** Follows from items 1/10 once the PO marks the
field groups. The WP-11.1 report vocabulary (INVOICE_CANDIDATE_HEADER |
INVOICE_CANDIDATE_LINES | CUSTOMER_CANDIDATE | PRODUCT_CANDIDATE | OTHER)
is the available classification surface (FROZEN as report labels only —
they carry no authority).

## 12. What enters through the Canonicalization Gate

**FROZEN (mechanism) + REQUIRES PO DECISION (scope).** FROZEN: the ONLY
sanctioned entry into Canonical is the full External Flow (AS-01) through
the Canonicalization Gate; a bypass is structurally impossible in the
frozen code. REQUIRES PO DECISION: which Holoo-sourced material (if any)
is FED to that flow (as captured documents? as adapter-synthesized input
documents? — the input format itself is part of item 1/8).

## 13. What must never create Sale/Inventory/KPI

**FROZEN.** DEF1 (no External→Sale), AD-03 (no inventory effects from
External Capture in MVP), D-06/DEF3 (no auto-create Customer). KPI is not a
Kandoo MVP domain (AD-02's 11-domain boundary contains no KPI domain).
These prohibitions bind any future adapter and need no decision.

## 14. Live DB connectivity requirements

**REQUIRES PO DECISION + REQUIRES REAL-HOLOO EVIDENCE.** The WP-11.1 spike
is offline-safe (SQLite file, mode=ro). A LIVE connection (network host,
SQL Server/ODBC driver, credentials, read-only SQL login, firewall,
file-share exposure of the .bak/.mdf) is infrastructure the PO/operator
must specify and provide. The agent made no connectivity assumption.

## 15. ODBC/SQL Server assumptions

**REQUIRES REAL-HOLOO EVIDENCE (with a FROZEN boundary note).** Evidence
needed: Holoo's actual DB engine/version (e.g., SQL Server edition), schema
stability, view availability, and whether a read-only replica can be
exposed. FROZEN boundary note: whatever the engine, the Canonical side must
remain source-agnostic (D-04) — an Adapter may translate, but no Holoo
schema/type may leak into Canonical. Stdlib-only project pattern (declared
in every WP) means any ODBC driver dependency is ALSO an explicit PO/TM
dependency decision.

## 16. Required sample datasets

**REQUIRES PO DECISION / OPERATOR ACTION.** To proceed safely WITHOUT any
live connection, the PO can supply: (a) a Holoo-schema DDL/documentation
dump, (b) read-only extracted samples (CSV/SQLite) of invoice
header/line/customer/product tables, (c) known-edge-case examples (reprints,
corrections, multi-page, mixed VAT). The WP-12.1 corpus mechanism (this
mission) provides the synthetic calibration scaffold the real material
would slot into (origin-role extension = explicit contract change).
