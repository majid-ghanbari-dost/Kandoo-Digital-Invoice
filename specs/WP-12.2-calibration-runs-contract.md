## §1 Purpose

WP-12.2 runs the FROZEN pipeline (AS-01 external sequence, through the P6.1
Canonicalization Gate) over a VERIFIED WP-12.1 corpus inside an ISOLATED
calibration workspace, compares the pipeline's outputs against the corpus
DECLARED ground-truth labels, and emits ONE deterministic CALIBRATION REPORT
(measurements only). The report gives the PO the measurement evidence for
WP-12.3 (G4): observed field-agreement counts, document outcome
distribution, and the D-08 tolerance-candidate sensitivity sweep.

The run is an instrument, not a pipeline stage. It writes NOTHING outside its
own workspace, mutates NO frozen store, creates NO production domain object,
and decides NOTHING. No threshold is evaluated as pass/fail; the report
counts observations and stops there (D-07/D-08 placeholders remain
placeholders until PO/G4 ratification).

## §2 Normative boundaries (absolute)

1. REPORT ONLY. The calibration layer's only output is an in-memory
   deterministic report object; a RUNNER (script, not the package) may write
   the report bytes to disk. No threshold ratification, no pass/fail verdict
   against D-07 placeholders, no parameter change anywhere.
2. ISOLATED WORKSPACE. Every pipeline store the run creates lives under the
   caller-provided workspace directory. The run NEVER opens a production
   store path, never reuses a workspace across runs, and never writes
   outside the workspace (path-provenance probes in the tests).
3. FROZEN PIPELINE, VERBATIM. The frozen services are consumed exactly as
   the frozen compositions consume them — no re-implementation of any
   pipeline semantics, no second normalization/validation/identity/gate
   logic. The measured path is capture → reconstruction → extraction →
   evidence binding → normalization → derivation → validation (declared
   reference rules) → P5.2 domain projection → P6.1 gate. The P6.2 assembly
   is NOT part of this WP's measured path (line-level calibration is future
   work with real corpus material).
4. NO TEST-HELPER IMPORTS. The production stack wiring is self-contained
   (the test helpers are test surface and are never imported by production
   code — AST-swept).
5. NO SIDE EFFECTS ON THE CORPUS. The corpus store is opened READ-ONLY in
   effect: the run consumes a verified CorpusReadSuccess and never writes to
   the corpus store (byte-stability proven in tests).
6. NO DOMAIN PROMOTION. No Sale (DEF1), no Customer (D-06/DEF3), no
   inventory effect (AD-03), no Digital Invoice, no REVIEW-queue semantics
   beyond consuming the frozen pipeline's own outcomes. Gate decisions in
   the workspace are pilot observations — they never leave the workspace.
7. DETERMINISTIC REPORT. The report is a pure function of (corpus content,
   declared run configuration): no wall-clock, no uuid bookkeeping values,
   no filesystem paths, no environment. Two fresh workspaces + the same
   corpus + the same config → BYTE-IDENTICAL report JSON.
8. ONE RUN PER WORKSPACE. A workspace records its run; a second run against
   a used workspace is a typed refusal (fresh workspace required). This
   keeps every measurement first-contact and replay-honest.

## §3 The declared run configuration (RunConfig)

All parameters are DECLARED by the caller and echoed verbatim in the report:

```text
corpus_version_id       — the WP-12.1 content address under calibration
origin                  — the declared capture origin for the pilot flow
                          (ORIGIN_HOLOO_CAPTURE — the synthetic pilot
                          material stands in for external POS capture)
engine_id               — extraction engine (reference-delimited-v1)
norm_ruleset_id         — normalization ruleset (kandoo-norm-v1)
vsm_ruleset_id/version  — domain projection ruleset (kandoo-vsm-rules / 1)
formula_id/version      — the reference derivation formula
                          (kandoo-der-total-gross-from-net-tax / 1)
tolerance/precision/mode— the DECLARED reference-rule R2 parameters
                          (D-08 calibration parameters, injected — never
                          hardcoded; today's declared values are the
                          D-08 placeholders, echoed but NOT ratified)
candidate_tolerances    — the DECLARED D-08 sweep candidates (ordered tuple
                          of canonical decimal strings ≥ 0)
identity_binding        — the D-02 role → source-field binding (declared)
agreement_rule_id       — kandoo-cal-declared-gross-agreement (§6)
```

## §4 Per-entry measured path (deterministic ladder)

For each corpus entry in ordinal order, inside the workspace stack:

```text
M1 capture      — aggregate(parts) → ingest(source_label="calibration");
                  a capture-level duplicate (D-03) continues on the EXISTING
                  capture id (honest replay; impossible in a fresh workspace
                  with distinct corpus documents, handled anyway).
M2..M5          — reconstruct → extract → bind → normalize (frozen services;
                  any typed failure ends the entry's path with the honest
                  stage marker and produces NO gate decision).
M6 derivation   — the declared reference formula; a deferred/unresolved
                  derivation is an OBSERVATION (it feeds the downstream
                  uncertainty route — D-01/D-08 territory), never an error.
M7 validation   — the FOUR declared reference rules (presence /
                  exact-consistency / tolerated-equality / rounded-equality)
                  over the declared reference registry.
M8 projection   — the declared domain-projection ruleset over the reference
                  rule keys (P5.2 verified vocabulary).
M9 gate         — canonicalize(domain_state_id, origin, identity_binding);
                  the outcome vocabulary is the FROZEN gate vocabulary
                  (ACCEPTED | REVIEW | REJECTED) or the honest NOT_REACHED
                  stage marker.
```

## §5 Field observations (the D-07 measurement surface)

After M5, the normalization record is read VERIFIED and compared against the
entry's declared labels:

```text
label VALUE     — exactly one NORMALIZED row for the field whose normalized
                  value equals the expected canonical string → MATCH;
                  a row present but not equal, or non-NORMALIZED status
                  → MISMATCH (with the observed status/value class);
                  no row for the field → MISSING.
label ABSENT    — no row for the field → MATCH; any row → UNEXPECTED_PRESENT.
```

Classifications aggregate per field name across the corpus. The report
carries COUNTS ONLY — rates and threshold comparisons are WP-12.3's PO
decision space, not this WP's.

## §6 The D-08 tolerance-candidate sweep (declared rules — data, not behavior)

For each declared candidate tolerance t (in declared order), the runner
builds a FRESH candidate stack (its own sub-workspace stores) and validates
one DECLARED R2 tolerated-equality rule per entry:

```text
rule_id   kandoo-cal-declared-gross-agreement
target    total.gross  origin=normalized   (the document's PRINTED gross)
input     total.net, tax.amount  origin=normalized
expr      ADD(net, tax)
tolerance t (the candidate)
```

This measures the real-world disagreement the D-08 parameter governs: the
document-printed gross vs. the pipeline-derived consistency value. Entries
without a normalized total.gross row (the review-probe template) are counted
`not_evaluable` — honestly excluded, never guessed. Per candidate the report
carries: {tolerance, evaluated, within_tolerance, beyond_tolerance,
not_evaluable}. The candidate list is DATA; no candidate is endorsed.

## §7 The calibration report (the run's ONLY output)

Deterministic canonical JSON (sorted keys, stable separators, no wall-clock,
no uuid, no paths): configuration echo (§3), corpus address + entry count,
per-entry observations (ordinal, stage reached, reference-rule outcomes,
gate decision + reason, field classifications), aggregate counts per field
classification, aggregate gate-decision counts, and the §6 sweep table.
The report is returned in memory; a runner script may persist it. The
package itself writes nothing.

## §8 Failure semantics (typed, honest)

Unknown corpus / integrity-failed corpus → refusal before any pipeline
work. Used workspace → typed refusal. Pipeline typed failures end the
affected entry's path with a stage marker — the run continues with the
remaining entries (a corpus may legitimately contain uncertainty-probing
material) and the report says exactly what happened. Nothing is retried,
guessed, or silently skipped.

## §9 Testing obligations (binding)

Dedicated suite: happy-path run over a mixed corpus (clean + rounding-probe
+ review-probe) with the observed gate distribution and field classifications
pinned against the generator's declared ground truth; report determinism ×2
across INDEPENDENT workspaces (byte-identical JSON); sweep counts pinned per
candidate (±1/±2-cent residuals vs declared candidates); re-run refusal;
corpus-store byte stability across the run; workspace path provenance (no
writes outside; no production paths); AST probes (no test-helper imports; no
wall-clock in the report path; import allowlist = declared pipeline modules
+ corpus + capture); vocabulary sweep (no Sale/Customer/Inventory/Digital
Invoice semantics); full regression + additive-only frozen proof. Repeat
≥ 2 independent runs. Smoke runner (cold-start, 8 steps).
